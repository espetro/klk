# Design Tokens — Klk UI System

## Overview

Klk uses a semantic design token system built on Tailwind v4 with CSS custom properties. This documentation provides a complete reference for the design system, including base palette, semantic tokens, integration patterns, and usage examples.

## Base Palette

The base palette defines the raw color values that serve as the foundation of the design system. These are the source values that all semantic tokens reference.

| Token              | Hex Value | Purpose                            |
| ------------------ | --------- | ---------------------------------- |
| `paper-100`        | `#FDFBF7` | Warm global background             |
| `paper-200`        | `#F5F0E8` | Elevated surfaces, cards, sheets   |
| `ink-900`          | `#1A1612` | Primary text, strongest icon color |
| `ink-600`          | `#5C554D` | Secondary text, metadata, hints    |
| `accent-500`       | `#C45B3A` | Main brand accent (terracotta)     |
| `accent-400`       | `#D97B5D` | Softer highlight                   |
| `accent-olive-500` | `#7A8450` | Secondary accent (olive)           |

## Semantic Tokens

Semantic tokens provide meaning and context to the UI. These are the tokens that should be used directly in components and styles.

### Token Reference

| Token              | Maps To            | Usage                                             |
| ------------------ | ------------------ | ------------------------------------------------- |
| `bg-default`       | `paper-100`        | App background, default page background           |
| `bg-elevated`      | `paper-200`        | Cards, drawers, modal sheets, elevated surfaces   |
| `text-primary`     | `ink-900`          | Titles, body text, strong labels, primary content |
| `text-secondary`   | `ink-600`          | Supporting copy, timestamps, captions, metadata   |
| `text-inverse`     | `paper-100`        | Text on dark or accent-filled surfaces            |
| `action-primary`   | `accent-500`       | Main CTA, active chips, primary highlights        |
| `action-secondary` | `accent-olive-500` | Secondary action, category emphasis, chips        |
| `state-highlight`  | `accent-400`       | Focus states, onboarding prompts, hover glows     |

## Tailwind v4 Integration

Klk uses Tailwind v4 with the `@theme` directive for CSS custom properties. This approach enables both CSS and Tailwind class usage.

### CSS Custom Properties

The design tokens are defined as CSS custom properties in `apps/events/global.css`:

```css
@theme {
  --color-bg-default: #fdfbf7;
  --color-bg-elevated: #R5F0E8;
  --color-text-primary: #1a1612;
  --color-text-secondary: #5c554d;
  --color-text-inverse: #fdfbf7;
  --color-action-primary: #c45b3a;
  --color-action-secondary: #7a8450;
  --color-state-highlight: #d97b5d;
}
```

### Tailwind Class Generation

CSS custom properties with the `--color-` prefix automatically generate Tailwind utility classes:

```css
/* Generated by Tailwind v4 */
.bg-bg-default {
  background-color: var(--color-bg-default);
}
.text-text-primary {
  color: var(--color-text-primary);
}
.bg-action-primary {
  background-color: var(--color-action-primary);
}
/* etc. */
```

  background-color: var(--color-bg-elevated);

  padding: 0.5rem 1rem;
  border-radius: 0.375rem;

.secondary-button {
  background-color: var(--color-bg-elevated);
  color: var(--color-text-primary);
  border: 1px solid var(--color-state-highlight);

### Tailwind Class Usage

```jsx
// React component using Tailwind classes

  <div className='bg-bg-elevated border border-state-highlight rounded-lg p-4'>
    <h3 className='text-text-primary font-semibold mb-2'>{event.title}</h3>

    <button className='bg-action-primary text-text-inverse px-4 py-2 rounded'>RSVP</button>

// Category chip component
const CategoryChip = ({ category, isActive }) => (
  <span
    className={`
    px-3 py-1 rounded-full text-sm
    ${isActive ? 'bg-action-secondary text-text-inverse' : 'bg-bg-elevated text-text-secondary'}
  `}
  >
    {category}
  </span>
);
```

### TypeScript Usage

The theme is available as a TypeScript object for runtime access:

```typescript
import { theme } from '@klk/ui/theme';

// Accessing colors at runtime
const currentTheme = theme;

// Usage in components
const getButtonStyle = (variant: 'primary' | 'secondary') => {
  return variant === 'primary'
    ? { backgroundColor: currentTheme.actionPrimary }
    : { backgroundColor: currentTheme.bgElevated };
};

// Type-safe color usage
type ThemeColors = {
  bgDefault: string;
  bgElevated: string;
  textPrimary: string;
  textSecondary: string;
  textInverse: string;
  actionPrimary: string;
  actionSecondary: string;
  stateHighlight: string;
};

const useTheme = (): ThemeColors => {
  return theme; // TypeScript will enforce all properties exist
};
```

## Visual Hierarchy

The design system follows a clear visual hierarchy:

1. **Content First**: Event imagery, titles, and user content should be the primary focus
2. **Structure Second**: Cards, layouts, and containers provide organization
3. **Brand Accent Third**: Terracotta and olive accents provide moments of emphasis

## Opacity Modifiers Caveat

**Tailwind v4 opacity modifiers do not work reliably on CSS custom properties.**

❌ **Don't do this:**

```tsx
<View className='bg-action-primary/15' />  // Does NOT work with custom properties
<View className='bg-bg-elevated/50' />      // Opacity modifier ignored
```

✅ **Do this instead:**

```tsx
import { theme } from '@klk/ui'

// Use inline styles with rgba()
<View style={{ backgroundColor: 'rgba(196, 91, 58, 0.15)' }} />  // action-primary at 15%
<View style={{ backgroundColor: 'rgba(245, 240, 232, 0.5)' }} />  // bg-elevated at 50%

// Reference theme values for the hex
<View style={{ backgroundColor: `rgba(${hexToRgb(theme.actionPrimary)}, 0.15)` }} />
```

**Why**: Tailwind v4's opacity syntax (`/15`, `/50`) works on static color definitions but not on `var(--color-*)` custom properties. Use inline `style` props with explicit rgba values instead.

## Best Practices

- Use semantic tokens, not raw hex values, in components
- Reserve accent colors for important interactions and highlights
- Keep background colors warm and neutral to let content shine
- Use `text-secondary` for supporting information to reduce visual noise
- Apply `state-highlight` sparingly for focus and hover states
- For opacity, use inline styles with `rgba()` — opacity modifiers don't work on custom properties
