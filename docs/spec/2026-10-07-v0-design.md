# Klk v0 — Design Spec

**Status:** Draft v1.0 (2026-10-07)
**Supersedes:** the Expo/React-Native spike, preserved on the `legacy` branch.

---

## 1. Context & Learnings

The spike (`legacy`) proved the product shape — circles, events, RSVPs on Nostr —
and hit its dogfood gate with the loop implemented but never validated by real
users. It failed on **delivery economics**, not on the idea:

- **Toolchain tax**: 30–50min EAS builds, a distribution pipeline that died
  early and stayed dead, Metro/`@expo/ui`/Kotlin traps filling the notepad.
  Time-to-device was days, not minutes.
- **Protocol tooling tax**: patched `ndk-mobile`, gift-wrap debugging, bespoke
  strfry write-policy ops before a single user could RSVP.
- **Architecture drift**: two `EventForm` implementations diverged; CI sat red
  for months on a format nit.

**Design directives for v0** (user-confirmed):

1. Keep Nostr — it is **the contract** for an event-driven social network.
   Own the tooling: our own relay binary and a thin client layer, no patched
   upstream kits.
2. PWA-first — a URL is an install; features reach a phone the moment they
   deploy.
3. Private — legal-grade: on sealed content the operator cannot produce
   plaintext. Tiered per circle so AI features can exist where they're allowed.
4. Additive — friends/family-sized circles first; no growth mechanics.
5. AI-first — agents are first-class participants, but the data is the moat:
   no bulk-export API; scoped capabilities only.
6. Runs E2E on any laptop and on a <1GB VPS.

## 2. v0 Loop (unchanged from spike)

**create circle → invite ≥3 people → post event → RSVP**

Success metric: 5 dogfooders complete the loop independently; time-to-first-
value (land → inside a circle) under 5 minutes on a real phone.

Non-goals for v0: public discovery surface (map/calendar/feed promotion),
group chat, push notifications, native shells, billing, Marmot/MLS,
federation beyond multi-relay reads.

## 3. Architecture

```
apps/
  pwa/          Web app — the whole product surface
  relay/        Go binary — our Nostr relay + product backend (one process)
packages/
  proto/        TS domain layer over nostr-tools: kinds, codecs, signers
  core/         Pure domain logic (no IO): circle/event/rsvp rules
  ui/           Shared presentational components + theme
```

### 3.1 Backend: `apps/relay` (Go + khatru)

A single Go binary built on **khatru** (`fiatjaf.com/nostr/khatru@master` —
the GitHub repo is in maintenance mode; pin the new module path and vendor a
fork only if we need internal changes). Chosen over strfry/nost-rs-relay
because our relay needs product logic, not just config:

- `RejectEvent` / `RejectFilter` hooks implement **per-circle write ACLs**,
  hosted-vs-sealed routing, rate limits, and per-pubkey quotas in code.
- `OnAuth` (NIP-42) binds every subscription to a pubkey scope.
- Eventstore: BoltDB (or SQLite) — a single file, no external services,
  fits the <1GB budget with headroom.
- Serves the PWA's static assets too (embed.FS) so the whole deploy is one
  binary + Caddy; `docker compose` used for local dev only.
- Extension surface for the AI tier (Q8b later): internal tool registry on
  the same code path as the client-facing scoped API.

Rejected: strfry (subprocess write-policy per event — wrong shape),
nostream (Postgres+Redis — too heavy), nostr-rs-relay (config-level, not a
framework), Elixir (thin Nostr ecosystem).

### 3.2 Frontend: `apps/pwa` (One + TypeScript PWA)

- Framework: **One** (`onejs/one`, MIT) — a Vite-based React framework whose
  whole point is our exact constraint: one codebase → web now, React Native
  later, with shared typed file-system routes and loaders. Replaces "Vite +
  React" plus a hypothetical native rewrite: native ships later as RN from
  the same tree, not a second app.
- Render mode: **SPA** (client-rendered; the app lives behind identity +
  live data anyway). SSG currently crashes in the stock template — no need
  for it in v0.
- PWA shell: `vite-plugin-pwa` (manifest + service worker) — install via
  Add-to-Home-Screen; Web Push plumbing ships now, notifications deferred.
- Universal UI via **Tamagui** (One's intended pairing, SSR-safe theming) —
  components live in `packages/ui`; one component set means web/native
  parity and the "exactly one EventForm" rule is enforced by construction.
- Layout: mobile-first single column + bottom tab bar
  (Events / Circles / Create / Profile). Event UX references: Luma
  (cover-first cards, sticky RSVP CTA) for events; GroupMe/Discord for
  circles; Nextdoor for the local feed shape.
- Maps: **MapLibre GL JS** + OpenFreeMap tiles (no API key, no tracking —
  on-brand for privacy; PMTiles/Protomaps self-host option documented).
  On the later RN path, `@maplibre/maplibre-react-native` keeps the same
  tile/style stack — the spike's "native maps only" rule was an RN-native
  constraint and no longer applies on web.
- Nostr access goes through `packages/proto`, our thin layer over
  **nostr-tools** (Unlicense, most-maintained minimal lib): NIPs 01, 42,
  44/59, 52 (+17 gift-wrap plumbing when needed). No NDK.
- State: nanostores (carried from spike — atomic, RN-free).
- Toolchain caveat: `one` needs **Node** for dev/build (Bun hits a V8
  callsite crash); pin Node via mise. **pnpm** is the package manager
  (not bun — pnpm's workspace + strict layout plays better with Vite/RN
  monorepos and CI caching).

### 3.3 Identity

- Nostr keypair per user, generated client-side on first run (NIP-06
  derivation optional for recovery-phrase purists).
- **Passkeys (WebAuthn) gate identity access**: nsec stored encrypted at rest
  (key wrapped by WebAuthn PRF where supported; passphrase fallback). No
  email, no magic-link dispatcher, no password.
- Lost-key recovery: PRF-gated export/backup; honest UX copy that sealed
  circles are unrecoverable if the key is lost.

## 4. Data Model (on the Nostr contract)

| Concept           | Kind / mechanism                                       |
| ----------------- | ------------------------------------------------------ |
| Event (calendar)  | NIP-52 kind 31923 (addressable)                        |
| RSVP              | NIP-52 kind 31925                                      |
| Circle definition | kind 31950 (addressable): name, tier, `invite` secret  |
| Circle membership | kind 31951 member-claim carrying the `invite` secret   |
| Hosted circle msg | plaintext-to-relay, server-readable (AI tier)          |
| Sealed circle msg | AES-GCM shared-key encrypted content (port from spike) |
| Agent scopes      | kind 34134 delegation events (addressable; see §5)     |

**Reads are NIP-42-gated**: anonymous connections can't query; filters
referencing a circle coordinate require membership (owner or accepted
member-claim). Writes are checked per circle: circle-scoped content
requires membership; member-claims require the circle's invite secret
(carried in the invite link); invite-less circles are closed.

**Per-circle privacy tier** is set at creation: `hosted` (server-readable;
AI features on) or `sealed` (shared-key E2EE; relay stores ciphertext).
Per-circle subsumes per-server: a sealed-only third-party relay is just a
relay where every circle is sealed. Our relay must serve both kinds to be a
good citizen of the relay network.

## 5. Agent Surface (AI-first, moat-preserving)

v0 exposes a **scoped capability API** — authenticated per-user (signed
delegation token bound to a pubkey + scope), where "scope" is a list of
circle coordinates the user's own client already has access to:

**How it works (v0, implemented):** the agent is a first-class Nostr
identity with its own keypair — it never holds the user's key. A member
publishes a kind-34134 **scope** event (`d` scope id, `p` agent pubkey,
`a` circle coord ×N, `cap` ×N, optional `expiration`). Scope kind moved
from 24134 → 34134 because kinds 20000-29999 are ephemeral (NIP-16) and
relays don't store them.

- **Writes (`act_as_user`):** the agent authors the event itself (kind
  31923/31925) with a `delegation` tag → the scope coordinate. The relay
  admits it iff the scope is live, covers that circle + capability, and
  the delegator is still a member. Caps: `postEvent` (31923), `setRsvp`
  (31925); circle defs, claims, and scopes are never delegatable.
- **Reads (`read_as_user`):** every filter must reference a circle it can
  touch (explicit `a` refs, or `d`+`authors` def lookups) — membership or
  a live `read` scope required per circle. Unscoped kind filters are
  rejected outright (**no bulk-scan surface**); kind 0/3 metadata and
  single-item `ids` lookups stay open.
- **Rate limits:** delegated writes are quota'd per agent pubkey
  (60/hour sliding window, in-memory).
- **Revocation:** addressable scopes replace by (delegator, `d`) —
  re-publish an emptied/expired scope to revoke; delegator leaving the
  circle auto-revokes. Audit trail = the signed events themselves.

Later (paid tier): hosted agent runtime — same tool schema, run inside our
boundary with bring-your-model-key. In-product assistant rides the same
tools. Agents never get broader rights than the user they act for.

## 6. Infra & Dev Loop

- **Local E2E**: `docker compose up` — relay (Go), PWA dev server, seed
  script publishing a demo circle+event; `--profile tunnel` adds cloudflared
  for LAN/public links. Compose services are small (Go binary, static dev
  server, SQLite-in-container); no Postgres, no Redis. Pinned resource
  limits in compose (`mem_limit`) so local dev can't exceed the VPS budget.
- **Deploy**: systemd units on the VPS — `klk-relay` (the Go binary) +
  Caddy. <1GB total: relay target <150MB RSS idle.
- **CI**: `pnpm -r validate` (tsc + oxlint + oxfmt on TS; `go vet` +
  `gofmt -l` + `go test ./...` on Go), plus a `compose`-level smoke test
  that boots the stack and runs the v0 loop via the scoped API.
- **Testing**: unit in both languages; E2E = scripted loop test against the
  compose stack (API-level, not UI-automation). Browser UI checks deferred
  to dogfood phase.

## 7. Migration

- `legacy` branch keeps the spike untouched.
- `main` was overwritten at the tree level (one commit replacing all
  files; branch protection blocked a force-push, and history retention
  is free anyway) — no code ported wholesale; `packages/core` concepts
  and the AES-GCM circle crypto get ported piecemeal during
  implementation.
- Repo shape preserved: conventional commits, atomic deployable commits,
  `pnpm -r validate` before every commit (AGENTS.md carries the rules).

## 8. Open Questions / Deferred

- **Marmot/MLS** is the documented v2 upgrade for `sealed` circles (forward
  secrecy, member churn) — blocked on a viable TS path; watch
  marmot-protocol JS bindings; spike's shared-key AES-GCM bridges v0.
- **Native**: revisit post-PMF — via One's RN path from the same tree
  (not a rewrite). Re-entering simulator/EAS territory then needs the
  harness fix (Maestro E2E, self-hosted OTA: updraft/xprem). Capacitor is
  the fallback if the RN path re-runs into the spike's wall. scriptc /
  PerryTS watchlist; Lynx rejected (embedded-only).
- **NIP-77 negentropy** sync between relays — v2 federation concern.
- **Passkey → nostr-key recovery UX**: PRF-extension support matrix across
  platforms needs verification during implementation; fallback = encrypted
  backup blob + passphrase.
- ~~**Circle membership kind**~~ decided at impl: custom kind 31951
  member-claim + `invite` secret tag. NIP-51 encrypted lists were the
  alternative but the relay can't enforce read/write ACLs on membership
  it can't see — claims stay visible (pseudonymous pubkeys only).
- **Invite transport**: link+code (v0) vs NIP-17 gift-wrap DMs (nicer but
  requires recipient to already be on Nostr) — v0 uses invite links;
  gift-wrap delivery as a bonus when the invitee has a pubkey.
